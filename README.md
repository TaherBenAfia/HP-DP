
HyperPersonalizedDataPipeline
# Test push workflow - CI pipeline verification

A local-first, cloud-independent data pipeline platform that transforms raw datasets into **auditable, statistically validated, action-oriented data products**. It implements a full layered pipeline — Bronze → Silver → Analytics → Statistics → Actions → Gold → Sharing — built on a research base model with synthetic data generated by SVTP (proxy model).

The pipeline architecture is domain-agnostic; the first implementation demonstrates the framework using a synthetic dataset derived from available page/SERP signals, where SVTP serves as the proxy for search visibility scoring.

## Architecture

```
raw data ──► BRONZE  (immutable copy + schema contract + checksum)
              │  src/ingestion/  ── validation, quarantine, ingestion log
              ▼
           SILVER   (typed, deduplicated, quality-scored facts)
              │  src/transforms/  ── normalization, 34 rows quarantined, 0 duplicates
              ▼
           ANALYTICS (research base model)
              │  src/analytics/  ── method registry, feature registry, SVTP visibility,
              │                 statistics, action families, metrics
              ▼
           GOLD     (published Delta tables + evidence + lineage)
              │  data/gold/*.delta
              ▼
           SHARING  (manifests, DuckDB query engine, JWT-protected API, dashboard)
                     sharing/manifests/ · src/query/ · src/sharing/ · app.py
```

Generic engines live in `src/analytics/`, `src/statistics/`, `src/query/`, `src/sharing/`; plugins integrate through `src/domains/base.py` and never leak into the generic code.

| Layer | Code | Output |
| --- | --- | --- |
| Bronze | `src/ingestion/` | `data/bronze/` (Delta), quarantine |
| Silver | `src/transforms/` | `data/silver/` (valid records / quarantined) |
| Analytics | `src/analytics/`, `src/statistics/` | features, tests, FDR-significant results |
| Gold | `src/domains/.../pipeline.py` | Delta tables in `data/gold/` |
| Sharing | `src/sharing/`, `src/query/`, `app.py` | manifests, API :8080, dashboard :8501 |

## Quickstart

### Using uv (recommended)

```bash
# Install dependencies
uv sync --all-extras

# Run the full pipeline
uv run python -m platform_cli run all

# Run tests
uv run pytest

# Run lint
uv run ruff check .
```

### Using pip

```bash
pip install -e ".[platform,dev]"

python -m platform_cli run all        # Bronze -> Silver -> Gold (idempotent)
python -m platform_cli stats summary  # statistical evidence overview
python -m platform_cli query "SELECT primary_action, count(*) AS n FROM action_recommendations GROUP BY 1"
python -m platform_cli lineage trace gold/action_recommendations
python -m platform_cli share list

streamlit run app.py                  # dashboard (7 pages)
uvicorn src.sharing.api:app --port 8080   # read-only JSON API
```

Individual steps: `ingest start [--force]`, `silver build`, `analytics run`.
Dataset/contract inspection: `datasource list|info|validate`.

### Prefect flows

```bash
python -m flows.pipeline_flow   # silver-to-gold flow (quality gate included)
python -m flows.scheduled       # scheduled daily ETL
```

## Research Base Model & SVTP Proxy

The platform is built on a **research base model** with **synthetic data** generated by **SVTP (Search Visibility Trend Proxy)**. SVTP is a proxy model built from available page and SERP signals.

### Research integrity rules (enforced in code and tests)

1. Observational study only — **no causal claims** anywhere in outputs.
2. SVTP is a proxy; available signal components are explicitly flagged (`signal_component_available = false`) and contribute a neutral value.
3. Derived platform columns are declared in the contract with `present_in_source: false`; they are never presented as measurements.
4. Zero-variance features are excluded from statistics and family scores.
5. Action scores are transparent heuristics, not forecasts; every row carries its JSON `evidence_features`, a `reason`, and a recommendation.
6. Benjamini–Hochberg FDR control at `alpha = 0.05` on every family.

### SVTP proxy model construction

- Built from measured page/SERP signal deficits re-weighted by FDR-significant statistical evidence
- Scores ranged [0, 1] and re-weighted by statistical significance
- Available signal components are documented and explicitly marked as available/unavailable
- No Google Search Console, CTR, or Trends data is available or simulated

## Testing & lint

```bash
ruff check .
pytest                # 168 tests: unit + platform + integration + legacy DVDCF
```

`tests/unit/` covers the generic engines, `tests/platform/` the config, contracts and lineage, `tests/integration/` the full Bronze→Gold pipeline, query engine and API (including authentication).

## Configuration & secrets

`configs/platform.yaml` is the single control file (paths, statistics, visibility weights, action thresholds, sharing auth). Placeholders such as `${SHARING_JWT_SECRET:-}` are expanded from the environment — copy `.env.example` to `.env` for local overrides.

docker compose up --build          # api :8080 + dashboard :8501
